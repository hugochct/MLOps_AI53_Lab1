## Milestone 1

**Question:**

- **`pyproject.toml`**: The project’s main configuration file. It describes the Python project, its dependencies, supported Python versions, and tool settings.

- **`uv.lock`**: A lock file generated by **uv**. It records the exact versions of all installed dependencies, including indirect dependencies, so everyone can recreate the same environment reliably.

- **`.venv/`**: The project’s local Python virtual environment. It contains the selected Python interpreter and installed packages, isolated from other projects and from the system Python installation.

## Milestone 2

**Engineering checkpoint 3:**

- Git remote: Stores the project’s source code, configuration files, documentation, and Git-tracked metadata such as .dvc files.

- DVC remote: Stores the actual versioned data files and other DVC-managed artifacts, such as the raw images.

- Does git push transfer the DVC-managed raw images ? No, git push transfers only Git commits and metadata; the images require a separate dvc push.

## Milestone 4

- **Should PREPARE depend on `reports/data_quality.json`?**  
  Yes. PREPARE should depend on VALIDATE’s data-quality report.

- **Should PREPARE also depend directly on `data/raw`?**  
  Yes. PREPARE reads the raw images directly, so changes to `data/raw` must trigger it.

- **Which `params.yaml` changes should rerun TRAIN?**  
  These parameters:

  - `data.image_size`
  - `train`
  - `augmentation`
  - `compute`
  - `tracking`

- **Why should EVALUATE track `selection.run_id`?**  
  Because it identifies the MLflow model being evaluated. Changing the selected Run can change the evaluation results.

- **Which file contains the scores DVC should track as metrics?**  
  `reports/test_metrics.json` is declared as a DVC metric with `cache: false`.

## Milestone 5

- **Git** records the source-code version used for the training Run and whether the working tree contained uncommitted changes.
- **DVC** records the pipeline dependencies, parameters, and generated data/model/report outputs used to reproduce the Run.
- **MLflow** records the Run’s parameters, dataset input, metrics, artifacts, model, and execution metadata.
