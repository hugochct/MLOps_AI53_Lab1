## Milestone 1

**Question:**

- **`pyproject.toml`**: The project’s main configuration file. It describes the Python project, its dependencies, supported Python versions, and tool settings.

- **`uv.lock`**: A lock file generated by **uv**. It records the exact versions of all installed dependencies, including indirect dependencies, so everyone can recreate the same environment reliably.

- **`.venv/`**: The project’s local Python virtual environment. It contains the selected Python interpreter and installed packages, isolated from other projects and from the system Python installation.

For the setting-change row, I would label the change as “rerun.” If data.image_size changes in params.yaml, PREPARE must run again because dvc.yaml declares data.image_size under PREPARE’s params. TRAIN must also run again because it declares data.image_size as a parameter and depends on the processed data generated by PREPARE. VALIDATE should not run because it does not declare data.image_size and its inputs remain unchanged.

For the file-edit row, I would edit src/train.py and label only TRAIN as “rerun.” TRAIN lists src/train.py as a dependency in dvc.yaml, so DVC detects that its input changed. VALIDATE and PREPARE should be skipped because their declared inputs and parameters remain unchanged. Their outputs do not need to be regenerated.

**Question:**

My main validation metric will be validation macro-F1 because it gives equal importance to all classes and is more informative than accuracy if class performance differs.

If two Runs have the same macro-F1, I will choose the Run with the higher validation accuracy. If accuracy is also tied, I will choose the Run with the lower validation loss.

I expect a lower learning rate to make training slower and produce smaller parameter updates. With the fixed number of epochs, it may lead to slower convergence and lower final validation scores, but it can also make training more stable and reduce the risk of overshooting a good solution.
